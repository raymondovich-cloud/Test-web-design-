# LifeGame — Fixed Version Project

**Статус документа:** BASELINE  
**Дата фиксации:** 06.10.2026  
**Назначение:** хранить только явно зафиксированные пользователем этапы, архитектурные и продуктовые решения.

## 1. Правило документа

Этот документ содержит полный набор явно зафиксированных базовых решений.

Он не является CURRENT state и не заменяет проверку фактического кода и тестов.

Если текущий код изменился после фиксации, BASELINE не обновляется автоматически. Новая фиксированная точка требует отдельного согласования.

## 2. Архитектурная модель

LifeGame использует Clean Architecture.

Зафиксированная структура:

- `core/`;
- `domain/`;
- `application/`;
- `presentation/`;
- `infrastructure/`;
- `memory/`;
- `index/`;
- `design/`.

`index/` — отдельная архитектурная подсистема расчётных показателей.

`design/` — отдельная независимая Design System, не являющаяся бизнес-слоем.

### 2.1. Зафиксированные границы

- Domain не хранит пользовательские данные.
- Domain не обращается напрямую к Memory.
- Application координирует Domain, Memory, Index и Presentation.
- Presentation не содержит бизнес-правила и не обращается напрямую к хранилищу.
- Infrastructure содержит технические реализации.
- Memory отвечает за состояние.
- Index содержит расчётные показатели.
- Design System отделена от бизнес-логики.
- Пользовательские и системные данные разделены.
- Security является архитектурной частью системы.

## 3. Продуктовая структура

Зафиксированы четыре пользовательских модуля:

1. Finance;
2. Health;
3. Development;
4. Profile.

Finance — Module 01 и стартовый модуль приложения.

## 4. Finance

Finance разделён на две отдельные поверхности:

### Finance Main

Основной финансовый dashboard включает:

- Financial Health;
- Capital;
- Data;
- сводные показатели;
- переходы к аналитике и управлению данными.

### Finance DATA

Зафиксированы шесть блоков:

1. Assets / Активы;
2. Actual income / Фактически заработанно;
3. Financial burden / Финансовая нагрузка;
4. Mandatory expenses / Обязательные траты;
5. Financial cushion / Финансовая подушка;
6. FSI 2.1 / Financial Stability Index.

Finance Main и Finance DATA не смешиваются.

## 5. Assets

Первый финансовый блок — Assets / Активы.

Активы являются частью имущественной картины пользователя и не ограничиваются только ликвидными средствами.

Зафиксирована возможность различать ликвидные и неликвидные активы.

Актив не считается автоматически деньгами, доступными для немедленного расходования.

## 6. Financial burden

Финансовая нагрузка разделяет:

- `debt` — задолженность;
- `payment` — регулярный платёж.

Эти понятия не смешиваются.

## 7. FSI 2.1

Официальная терминология финансового индекса — **FSI 2.1 — Financial Stability Index**.

Устаревшие обозначения не являются частью зафиксированной текущей терминологии.

## 8. Design System

Зафиксирована единая dark-first Design System:

- чёрные и графитовые поверхности;
- белая и мягко-серая типографика;
- сдержанный оранжевый акцент;
- мягкие градиенты;
- тонкие границы;
- умеренные радиусы;
- минимальные тени;
- отсутствие визуального шума;
- премиальный системный характер.

Design System должна оставаться независимой от бизнес-логики.

Finance DATA использует общую Design System; строки внутри блоков не должны превращаться в отдельные яркие карточки.

## 9. Пользовательские взаимодействия Finance DATA

В зафиксированной Finance DATA-модели сохранены:

- закрепление;
- редактирование;
- удаление свайпом влево;
- добавление;
- раскрытие категорий;
- ограничения подписочного уровня, если они предусмотрены реализацией.

## 10. Main Finance и экспериментальные интерфейсы

Экспериментальный интерфейс `FINANCIAL SYSTEMS` не является утверждённой основной Finance-поверхностью.

Main Finance и Finance DATA сохраняют разные роли.

## 11. Документация и изменения

Зафиксировано обязательное:

- версионирование изменяемых файлов;
- ведение Change Log;
- разделение BASELINE, CURRENT, истории и планов;
- согласование изменений до их реализации.
