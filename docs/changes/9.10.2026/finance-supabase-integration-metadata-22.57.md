## Что изменено

После гидратации Supabase возвращает пользовательские записи вместе со служебными полями аудита `createdAt` и `createdBy`. Интеграционный тест теперь исключает эти поля из сравнений предметных данных, чтобы проверять контракт Finance без привязки к инфраструктурным метаданным.

## Причина

После устранения ошибки имени переменной тест дошёл до проверки persistence и упал, потому что сравнение ожидало только бизнес-поля, тогда как гидратированная запись дополнительно содержит метаданные хранения.

## Архитектурные решения

- Изменён только интеграционный тест; адаптер, схема и бизнес-логика не изменялись.
- Тест продолжает проверять сохранение и гидратацию бизнес-данных, а также изоляцию пользователей.
- Служебные метаданные не удаляются из приложения или базы данных.

## Проверка

- Все сравнения гидратированных записей используют проекцию бизнес-полей.
- Ожидается повторный результат GitHub Actions на `main`.
