## Что изменено

При нескольких Finance-изменениях в пределах одной миллисекунды снимки могли получить одинаковый `occurredAt`. Выбор снимка с условием строгого `>` сохранял первый снимок при равных отметках времени, из-за чего после удаления запись могла появляться снова из устаревшего snapshot.

Четыре выбора snapshot для состояния «на момент времени» и последнего snapshot теперь при равных временных отметках выбирают последний добавленный снимок. Обработка первых снимков не менялась.

## Причина

CI выявил два падения Finance Application lifecycle tests: после удаления данные читались из устаревшего snapshot, поскольку несколько операций происходили в пределах одной миллисекунды.

## Архитектурные решения

- Исправлена логика упорядочивания внутри Finance Memory; Domain и Application не изменялись.
- Сохранена изоляция слоёв Clean Architecture: snapshot ordering остаётся ответственностью Memory.
- Изменение не затрагивает пользовательскую схему БД и миграции.

## Проверка

- Проверены все четыре места выбора состояния snapshot при одинаковом `occurredAt`.
- Ожидается повторный запуск GitHub Actions на `main`.
