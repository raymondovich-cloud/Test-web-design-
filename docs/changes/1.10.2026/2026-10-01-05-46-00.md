## Что изменено

В `docs/agent.md` добавлено обязательное правило единой системы дизайна приложения.

Зафиксирован принцип:

> «design — это не один огромный design.js, а Design System из маленьких независимых модулей. Каждый файл отвечает только за одну категорию визуальных правил.»

Дополнительно зафиксированы правила:
- запрет монолитных файлов дизайна на тысячи строк;
- разделение токенов, фундаментальных правил, компонентов, UI-паттернов и тем;
- отсутствие зависимости Design System от бизнес-доменов;
- направление зависимостей `Domain → UI → Design System → Design Tokens`;
- запрет обратной зависимости `Design System → Domain`;
- обязательное переиспользование существующих компонентов и токенов вместо локального дублирования.

## Причина изменения

Необходимо заранее закрепить архитектуру единого визуального языка LifeGame и исключить постепенное превращение папки `design` в монолитный файл с тысячами строк.

## Архитектурное решение

Design System рассматривается как независимый архитектурный слой, состоящий из небольших модулей с одной визуальной ответственностью.

Бизнес-логика доменов не должна попадать в Design System.
