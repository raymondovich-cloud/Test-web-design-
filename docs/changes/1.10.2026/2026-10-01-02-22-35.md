## What changed

Added a mandatory two-stage development workflow to `docs/agent.md`:

1. Discussion and approval before repository changes.
2. Implementation only after the user's explicit confirmation of the selected solution.

The workflow also defines an explicit exception for requests where the user directly asks for implementation without preliminary discussion.

## Reason

To separate architectural/product decisions from implementation and prevent unapproved changes from being made directly in the repository.

## Important architectural decision

For normal change requests, GitHub modifications are prohibited during the discussion stage. The assistant must first clarify the task, inspect the applicable project rules, identify affected architecture/files, present meaningful implementation options when applicable, and wait for the user's explicit choice.

Only after approval may implementation, versioning, change logging, and Git commit take place.

## Result

The two-stage approval workflow is now part of the mandatory LifeGame project rules.
