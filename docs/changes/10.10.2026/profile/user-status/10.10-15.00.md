# Change Log — Динамический статус пользователя

- **Дата:** 10.10.2026
- **Время:** 15:00:00 MSK (UTC+03:00)
- **Пользовательский запрос:** после назначения роли Creator отображать соответствующий статус в настройках профиля вместо статического значения «Пользователь».
- **Изменённые файлы:**
  - `source/infrastructure/supabase/profile.adapter.js` — Version 1.1 → 1.2
  - `source/infrastructure/supabase/profile.adapter.test.mjs` — Version 1.0 → 1.1
  - `source/application/profile/profile.js` — Version 1.1 → 1.2
  - `source/application/profile/profile.port.js` — Version 1.1 → 1.2
  - `source/application/profile/profile.test.mjs` — Version 1.0 → 1.1
  - `source/presentation/profile/profile.js` — Version 1.6 → 1.7
  - `.github/workflows/preview-publish.yml` — Version 1.2 → 1.3
- **Описание:** статус читается из собственной строки `public.user_profiles` через Supabase-адаптер и Application-контракт. В интерфейсе роли отображаются как «Создатель», «Администратор» и «Пользователь». При ошибке чтения показывается нейтральное сообщение, настройки остаются доступными. CI дополнен запуском тестов Profile Application и Supabase Adapter.
- **Архитектурное решение:** Presentation не обращается к Supabase напрямую; роль передаётся через Application и Infrastructure. Запрос ограничен `user_id` текущего пользователя и опирается на существующую RLS-политику чтения собственного профиля. Email не используется как условие определения роли.
- **Причина:** ранее статус был жёстко задан в Presentation и не отражал роль аккаунта.
- **Статус:** IMPLEMENTED — код и автоматические тесты добавлены в тестовую ветку; результат нового CI-прогона требует проверки.
