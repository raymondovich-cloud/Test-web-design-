# Change Log — серверная граница записи дневника тренировок

- Дата: 10.10.2026
- Время: 15:32 МСК
- Ветка: `feature/pwa-static-cache`

## Цель

Закрыть прямой доступ пользовательских ролей к таблице тренировок и оставить операции чтения/записи через проверяемый серверный HTTP handler.

## Изменения

- Удалены table grants SELECT/INSERT/UPDATE для `authenticated`; доступ к таблице выдан только серверной роли `service_role` для нужных операций.
- Сохранены RLS и ownership policies как defense in depth.
- Trigger поддерживает доверенный серверный путь без `auth.uid()`, но продолжает проверять владельца, если user claim присутствует; identity и lifecycle invariants сохранены.
- Handler сначала проверяет JWT через Supabase Auth, и только после этого создаёт отдельный привилегированный repository client.
- Repository сохраняет явные `user_id` filters и owner binding на каждой операции.
- Database tests проверяют отсутствие прямых grants, блокировку прямого доступа, ownership trigger и CAS/lifecycle invariants.
- Security contract обновлён до Version 1.6.

## Безопасность и стоимость

- Не добавлялись ключи, secrets, AWS resources или платные сервисы.
- Не развёртывалась Edge Function.
- Удалённая Supabase база не изменялась; миграция остаётся только в GitHub.
- `service_role` должен быть настроен только в серверном окружении и никогда не передаваться браузеру, Telegram Mini App или iOS.
- AWS KMS и настоящее application-layer encryption остаются отдельным production gate; статический/вшитый ключ не вводился.

## Проверки

CI запускается после коммита. До завершения Database Tests изменение не считать проверенным полностью.
