## Дополнительная проверка CI — исправление SQL-теста

Время: 14:56 MSK (UTC+03:00)

- Первый полный GitHub Actions run завершился ошибкой только на pgTAP test 14 из 15 в training_sessions.
- Причина: assertion по форме encrypted envelope проверял запись User A уже после переключения JWT subject на User B. RLS корректно скрывал запись User A, поэтому тест получил 0 вместо 1. Это ошибка порядка/контекста самого теста, не ошибка RLS.
- Исправлено: проверка envelope теперь обращается к собственной записи User B. Миграция и политики доступа не изменялись.
- Все предыдущие шаги того же workflow, включая syntax, Service Worker, Finance/Application, Training Domain/Application, Training Infrastructure/Encryption, Identity/Profile и Finance Supabase persistence, завершились успешно.
- Повторный полный database workflow ожидает подтверждения после нового commit.


## Повторный CI — устранение гонки времени в существующем Development-тесте

Время: 14:58 MSK (UTC+03:00)

- После исправления RLS-aware SQL assertion новый CI дошёл до unit-test suite, но упал в source/application/development/development.test.mjs на проверке index.value.
- Причина — временная гонка: тест создавал recordedAt через Date.now() внутри async memory.listAllFacts(), а Application фиксировал now до await. Иногда факт оказывался на несколько миллисекунд в будущем относительно снимка времени и корректно отбрасывался latestWithinWindow.
- Сделан тест детерминированным: fixture использует timestamp на 1 секунду раньше текущего времени, чтобы проверять расчёт, а не планирование microtasks. Production Application/Domain поведение не менялось.
- Повторный CI требуется для подтверждения обеих правок.
