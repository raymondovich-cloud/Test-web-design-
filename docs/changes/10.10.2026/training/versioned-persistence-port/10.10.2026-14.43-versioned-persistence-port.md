## Реализовано

- Domain принимает UUID для ID тренировочной сессии и нормализует его к нижнему регистру.
- Первичное сохранение использует insertForUser, не upsert; Application создаёт ID и timestamps.
- Репозиторий возвращает envelope { session, revision }.
- Сценарии start/complete/revise требуют expectedRevision.
- updateForUser(userId, session, expectedRevision) должен атомарно выполнить compare-and-swap и вернуть новую revision либо null при конфликте.
- Application преобразует устаревшую revision или CAS miss в TRAINING_SESSION_CONFLICT.
- Добавлена проверка envelope результата репозитория и его ID.
- Тесты расширены проверками UUID, revision, stale revision, CAS miss и ошибки контракта репозитория.
- Документы фиксируют целевое прикладное шифрование payload AES-256-GCM и envelope encryption с KMS-managed KEK.
- CI workflow теперь запускает тренировочные Domain/Application тесты и реагирует на push в feature/pwa-static-cache.

## Границы и риски

- Не создавались таблица или SQL-миграция.
- Не реализованы Supabase-адаптер, CAS SQL, RLS policies, KMS, шифрование, UI и синхронизация.
- Конкретный KMS-провайдер должен быть выбран до реализации шифрования.
- Unit-тесты с mock repository не доказывают безопасность БД.
- Для финального коммита нет подтверждённого результата CI; статус тестов остаётся REQUIRES VERIFICATION.
