# Change Log — Диагностика жизненного цикла голосового ввода

- **Дата:** 10.10.2026
- **Время:** 16:00 MSK (UTC+03:00)
- **Запрос:** продолжить исправление голосового ввода после того, как предыдущая корректировка парсера не привела к заполнению полей на iPhone Safari.
- **Статус:** IMPLEMENTED IN REPOSITORY — добавлена явная обработка завершения распознавания без результата; требуется подтверждение CI, публикации и повторный тест на iPhone.

## Изменённые файлы
- `source/infrastructure/voice/speech-recognition.adapter.js` — Version 1.0 → 1.1.
- `source/presentation/finance/finance.js` — Version 7.21 → 7.22.
- `docs/changes/10.10.2026/finance/voice-input-lifecycle/10.10-16.00.md` — создан, Version 1.0.

## Причина
Адаптер раньше только возвращал управление при событии `onend`. Если Safari завершал прослушивание без события `onresult` и без явного `onerror`, приложение не объясняло, что текст вообще не был получен. Кроме того, адаптер читал только первую запись результата вместо обхода доступных финальных результатов.

## Что изменено
- Адаптер собирает финальные фрагменты распознавания с учётом `resultIndex`.
- Отслеживаются получение результата и ошибки в рамках одного запуска.
- Если Safari завершил прослушивание без результата, пользователю показывается конкретное сообщение вместо молчаливого завершения.
- Ошибки `no-speech`, доступа к микрофону и сети получают более точные подсказки.
- Интерфейс явно сообщает о процессе прослушивания и гарантированно показывает статус при получении результата.
- Заполнение полей остаётся предварительным: LifeGame не сохраняет запись автоматически.

## Архитектура и безопасность
- Инфраструктурный адаптер отвечает только за браузерный API и жизненный цикл распознавания.
- Presentation отвечает за статусы и заполнение формы; Application по-прежнему разбирает текст детерминированно.
- Не добавлены зависимости, AI, сетевые вызовы или запись аудио в код LifeGame.
- В диагностике не записываются произнесённый текст и финансовые значения.

## Проверки и ограничения
- Проверено, что рабочая ветка перед изменением соответствует ожидаемому HEAD.
- Изменение подготовлено отдельным коммитом с одним файлом журнала изменений.
- Успешная сборка не заменяет реальную проверку Web Speech API на iPhone Safari; после публикации нужно подтвердить, что интерфейс либо заполняет поля, либо показывает точную причину отсутствия результата.
