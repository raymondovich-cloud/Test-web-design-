# LifeGame — изменения 4.10.2026

## Исправление маршрутизации после авторизации

### Что изменено

- Исправлен возврат пользователя после регистрации/входа:
  - Finance → возвращение в Finance.
  - Health → возвращение в Health.
  - Development → возвращение в Development.
  - Profile → возвращение в Profile.
- Механизм pendingAction сохранён без изменения принципа работы: если авторизация была вызвана непосредственно перед защищённым действием Finance, действие выполняется после успешной авторизации.
- Profile добавлен в маршрутизацию приложения как отдельный модуль.
- Добавлен presentation-слой Profile без помещения пользовательских данных в Domain.
- Finance остаётся модулем по умолчанию.
- Исправлено начальное состояние index.html, где визуально был указан Development как активный модуль.

### Что не изменялось

- Supabase.
- Domain Identity.
- Application Identity.
- Auth adapter/mapper.
- Existing registration/login flow.
- Finance Domain и Memory.

### Проверочная логика

1. Гость находится в Finance и выполняет защищённое действие → после авторизации остаётся в Finance.
2. Гость находится в Health → после авторизации возвращается в Health.
3. Гость находится в Development → после авторизации возвращается в Development.
4. Пользователь открывает Profile после авторизации → Profile остаётся отдельной вкладкой и не заменяется Finance.
5. Гость открывает Profile → требуется авторизация; после неё восстанавливается Profile.

## Стабильность

Изменения ограничены web routing/presentation boundary и не затрагивают установленную auth-инфраструктуру.
