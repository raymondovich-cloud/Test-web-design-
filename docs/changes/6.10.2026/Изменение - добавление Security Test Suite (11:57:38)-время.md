## Пользовательский запрос

Создать в Security-документации папку `test.security`, содержащую правила проведения Security-тестов и основу набора файлов для последующего запуска полного теста безопасности проекта одной командой.

## Что изменено

Создан нормативный Security Test Suite:

- README определяет назначение, результаты и уровни воздействия;
- test-plan определяет порядок полного Security-аудита;
- test-manifest определяет идентификаторы и области проверок;
- `docs/agent.md` закрепляет test.security как нормативный контур Security-тестирования;
- `docs/project-state.md` фиксирует его как CURRENT.

## Архитектурные решения

1. Security-тестирование отделено от Security Architecture и Threat Model, но использует их как нормативные источники.
2. Наличие теста не считается доказательством реализации защиты.
3. SAFE, CONTROLLED и DESTRUCTIVE проверки имеют разные правила выполнения.
4. Полный аудит не считается успешным при невыполненных обязательных проверках.
5. Security Test Suite не исправляет найденные проблемы автоматически.

## Ограничение текущего этапа

На этом этапе создан нормативный каркас и manifest. Исполняемые тестовые сценарии и вспомогательные файлы будут добавляться отдельными изменениями по мере реализации конкретных проверок.

## Безопасность изменений

Код приложения, бизнес-логика, база данных, миграции и Security implementation не изменялись.
