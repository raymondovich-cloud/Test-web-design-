## Запрос

Разработать полноценный test-plan.md для Security Test Suite и зафиксировать правило, согласно которому Security-тесты запускаются исключительно относительно фактически существующей и реализованной структуры текущей версии проекта.

## Что изменено

test-plan.md расширен из краткого каркаса в операционный план Security-тестирования.

Зафиксированы:

- источники истины и их приоритет;
- обязательная предварительная проверка применимости каждого теста;
- запрет на запуск тестов для отсутствующих или не реализованных функций;
- разграничение CURRENT/IMPLEMENTED и PLANNED/FUTURE/EXPERIMENTAL;
- статусы применимости APPLICABLE, NOT APPLICABLE, NOT TESTED и REQUIRES VERIFICATION;
- запрет на искусственное создание отсутствующей продуктовой функции внутри Security-теста;
- порядок Phase 0–7;
- SAFE, CONTROLLED и DESTRUCTIVE;
- стандарт PRECONDITION → EXECUTION → OBSERVATION → EXPECTED → ACTUAL → STATUS → EVIDENCE → SEVERITY;
- статусы PASS, FAIL, WARNING, NOT TESTED, NOT APPLICABLE, REQUIRES VERIFICATION;
- уровни CRITICAL/HIGH/MEDIUM/LOW/INFO;
- требования к evidence;
- критерии завершения полного аудита;
- формат итогового отчёта;
- граница ответственности Security Test Suite.

## Архитектурные решения

1. Security Test Suite проверяет только фактическую текущую систему.
2. Наличие теста в manifest не означает наличие соответствующей реализации.
3. PLANNED/FUTURE/EXPERIMENTAL не превращаются в исполняемый CURRENT функционал.
4. Отсутствующая функция не является FAIL только потому, что для неё существует будущий Security-контроль.
5. Расхождение между документацией и реализацией получает REQUIRES VERIFICATION до однозначного определения фактического состояния.
6. Security-тест не создаёт отсутствующую продуктовую функцию для последующей проверки.
7. Security Test Suite не выполняет автоматическое исправление выявленных проблем.

## Причина

Предотвратить ложные Security findings, возникающие из-за запуска тестов на функции, которые ещё не реализованы в LifeGame, и сделать полный Security-аудит воспроизводимым относительно фактического состояния проекта.
