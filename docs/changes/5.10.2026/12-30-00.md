# Изменение LifeGame — 05.10.2026

## Проблема

После успешной авторизации Web Shell оставался в состоянии public, если URL hash не менялся. Из-за этого раздел Profile не появлялся сразу после входа, а попытка добавить и удалить строку в Finance воспринималась как действие неавторизованного пользователя и открывала Create account.

## Причина

После login/registration текущая реализация закрывала auth modal и либо повторно устанавливала тот же hash, либо выполняла pending action. Если hash уже был #finance, событие hashchange не возникало. renderRoute() не запускался, поэтому publicMode оставался true.

При переходе в Health или Development происходила новая маршрутизация, renderRoute() заново проверял Supabase session и переводил Web Shell в authenticated state. Поэтому последующее удаление строки уже работало корректно.

## Исправление

Изменён platforms/web/web.js — Version 2.5.

Добавлен единый handleAuthenticated(), который после успешной авторизации:

1. закрывает auth modal;
2. явно вызывает renderRoute();
3. переводит Web Shell в authenticated state без требования изменения hash;
4. только после обновления shell выполняет pending action, если он существует;
5. сохраняет текущий маршрут без лишнего изменения URL.

## Результат

Авторизация теперь должна сразу синхронизировать UI и состояние доступа. Дополнительный переход в Health/Development для появления Profile больше не требуется.

## Статус

Исправление внесено и закоммичено.

## План проверки

1. Открыть LifeGame.
2. Авторизоваться.
3. Не переходить в Health/Development.
4. Убедиться, что Profile отображается сразу.
5. Открыть Finance.
6. Добавить строку.
7. Удалить строку.
8. Убедиться, что Create account не открывается и пользователь остаётся авторизованным.
