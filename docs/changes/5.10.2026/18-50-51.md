# Исправление регрессии Finance write actions

**Дата:** 05.10.2026  
**Время:** 18:50:51 МСК (UTC+03:00)

## Проблема

После исправления logout снова проявилась регрессия: при попытке редактировать или удалить существующую строку Finance открывался экран создания аккаунта.

## Причина

Причина находилась в Web Shell и была связана с асинхронными route render.

При параллельных проверках сессии устаревший render мог завершиться после актуального render. В результате визуально авторизованный Finance мог получить `publicMode = true`.

Finance presentation использует `publicMode` для подключения write guard. В публичном режиме попытка изменения данных передавалась в `openRegistrationModal()`, поэтому вместо редактирования или удаления открывался Create Account.

Проблема не была связана с domain-операциями редактирования или удаления.

## Изменено

Изменён:

- `platforms/web/web.js` — Version 3.7.

Внесены следующие изменения:

1. Access state устанавливается до асинхронной загрузки user-scoped Finance Memory.
2. `renderApplicationShell()` получил контроль актуальности `renderId`.
3. Устаревший render не может изменить состояние текущего Web Shell.
4. Добавлена дополнительная проверка после завершения `createMemoryForUser()`.
5. Public render также получает и проверяет актуальный `renderId`.

## Архитектурный результат

Зафиксирована граница между authentication state и Finance write actions:

`authenticated session → authenticated Web Shell → Finance write actions`

Устаревший asynchronous render больше не должен переводить активный authenticated Finance UI в public write mode.

## Проверка

Пользователь подтвердил исправление.

Проверены сценарии:

- редактирование существующей строки;
- удаление существующей строки;
- работа Finance после переходов между экранами;
- отсутствие ошибочного перехода в Create Account при авторизованном состоянии.

## Статус

**Исправлено и согласовано.**
