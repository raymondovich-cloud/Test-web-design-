# Изменение архитектуры ликвидности активов — 05.10.2026 16:10:32 МСК

## Version 1.0

### Изменено

1. **Memory**
   - Проекции ликвидных и неликвидных активов теперь являются отдельным API Memory.
   - При отсутствии snapshot возвращается `null`, чтобы Application мог корректно отличить отсутствие исторического состояния от пустого набора активов.

2. **Application**
   - Application больше не классифицирует активы самостоятельно при наличии Memory.
   - FSI получает `liquidAssets` и `illiquidAssets` через специализированные Memory readers.
   - Сохранён fallback на Domain только до появления первого snapshot.

3. **Web composition**
   - Web composition передаёт в Application все три Memory readers:
     - общий snapshot;
     - ликвидные активы;
     - неликвидные активы.

### Проверка сценариев

#### Сценарий 1 — Ликвидно → Неликвидно

Ожидаемый поток:

`updateAsset(..., "illiquid")`
→ Domain публикует новое состояние
→ Web сохраняет snapshot в Memory
→ Memory projection `getLiquidAssetsAtOrBefore()` исключает актив
→ Application передаёт новый `liquidAssets`
→ Index пересчитывает FSI с меньшим объёмом ликвидных средств.

#### Сценарий 2 — Неликвидно → Ликвидно

Ожидаемый поток:

`updateAsset(..., "liquid")`
→ Domain публикует новое состояние
→ Web сохраняет snapshot в Memory
→ Memory projection `getLiquidAssetsAtOrBefore()` включает актив
→ Application передаёт новый `liquidAssets`
→ Index пересчитывает FSI с увеличенным объёмом ликвидных средств.

### Фактическая проверка

Проведена статическая проверка связки Domain → Event Bus → Memory → Application → Index.

Публичная GitHub Pages среда в текущем инструментальном окружении не позволила выполнить интерактивный браузерный тест, поэтому результат опубликованного UI не выдаётся за фактически воспроизведённый runtime-тест.

### Одобрено

Архитектурное решение: единый источник истины для Asset + производные liquidity projections в Memory.
