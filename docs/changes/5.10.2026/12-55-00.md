# Исправление гонки состояния авторизации

Дата: 05.10.2026
Время (МСК): 12:55

## Изменено

- `platforms/web/web.js` обновлён до Version 2.6.
- Добавлен последовательный идентификатор рендера маршрута.
- Устаревший асинхронный `getCurrentSession()` теперь не может перезаписать более новый авторизованный shell публичным состоянием.
- Добавлена такая же защита для устаревших ошибок проверки сессии.

## Причина

После авторизации могли одновременно выполняться несколько `renderRoute()`. Старый запрос проверки сессии мог завершиться после нового авторизованного рендера и вернуть Finance в `publicMode`. В результате обработчики добавления/удаления продолжали считать пользователя неавторизованным и открывали Create account.

## Ожидаемое поведение

После регистрации или входа:

1. Profile появляется сразу.
2. Finance остаётся в authenticated/private state.
3. Добавление и удаление строки сразу после авторизации не открывает Create account.
4. Переход в Health или Development больше не нужен для синхронизации состояния.

## Дизайн

Дизайн, структуру Finance и архитектурные границы не изменялись.
