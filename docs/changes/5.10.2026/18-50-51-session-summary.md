# Итог этапа разработки

**Дата:** 05.10.2026  
**Время:** 18:50:51 МСК (UTC+03:00)

## Изменено

Исправлена регрессия Finance, при которой авторизованный пользователь при редактировании или удалении строки попадал на экран создания аккаунта.

Причина была в устаревшем асинхронном Web Shell render, который мог установить `publicMode = true` после актуального authenticated render.

В `platforms/web/web.js` выполнены:

- ранняя фиксация access state перед асинхронной загрузкой Finance Memory;
- передача `renderId` в `renderApplicationShell()`;
- проверка актуальности render до изменения состояния;
- проверка актуальности render после `createMemoryForUser()`;
- защита public render от устаревшего результата.

Файл обновлён до **Version 3.7**.

## Утверждено

Этап согласован пользователем.

Зафиксировано корректное поведение:

- авторизованный пользователь может редактировать строки;
- авторизованный пользователь может удалять строки;
- Create Account не открывается при этих действиях;
- переходы между Finance и Profile не ломают состояние write actions.

## Проверка

Исправление проверено пользователем в рабочем интерфейсе.

## Архитектурное состояние

Текущий фикс защищает Web Shell от stale authentication render.

При этом module-global `financeMemory` в Application Finance остаётся временной архитектурной точкой и не считается финальным состоянием архитектуры.

## План

Следующий этап:

1. убрать глобальное активное Finance Memory;
2. закрепить user-scoped state на уровне Application;
3. окончательно оформить границу Application → Memory;
4. сохранить lifecycle-тесты Finance для create/update/delete/logout/login;
5. отдельно проверить изоляцию данных между пользователями.
