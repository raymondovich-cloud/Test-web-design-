# Этап: гостевая навигация и профиль

Дата: 5.10.2026

## Изменено

1. Нижняя навигация теперь использует один слот №04 для аккаунта.
2. Для неавторизованного пользователя слот №04 показывает «Авторизация» и ведёт на `#auth`.
3. Переход в «Авторизация» открывает существующее окно Create Account, без создания отдельного механизма авторизации.
4. После успешной авторизации слот №04 автоматически меняется на «Профиль» и ведёт на существующий Profile.
5. После выхода из аккаунта слот №04 снова меняется на «Авторизация».
6. Маршрут `auth` добавлен в web routing как гостевой маршрут.
7. Архитектура Identity, Supabase и Finance Memory не изменялась.

## Проверено

- В Finance уже существует write-guard для неавторизованного пользователя.
- Редактирование строки через long press перед открытием редактора проходит через `onWriteAttempt`.
- Удаление через iOS-like swipe также проходит через `onWriteAttempt`.
- Поэтому отдельные изменения в Finance для требования «при редактировании открыть Create Account» не потребовались.

## Архитектурное решение

Граница состояния аккаунта остаётся в Web Composition/Presentation boundary.

Navigation отвечает только за отображение и переключение account-slot между двумя состояниями:

- guest → Authorization;
- authenticated → Profile.

Identity Application и Finance Domain/Memory не получают зависимость от Navigation.

## План проверки в браузере

1. Открыть LifeGame без авторизации → увидеть 4 нижних пункта: Финансы, Здоровье, Развитие, Авторизация.
2. Нажать «Авторизация» → открыть существующее окно Create Account.
3. В Finance выполнить long press по строке → открыть Create Account вместо редактора.
4. Открыть swipe-delete и нажать «Удалить» → открыть Create Account вместо удаления.
5. Авторизоваться → увидеть в слоте №04 «Профиль».
6. Открыть Profile → убедиться, что используется существующий экран Profile.
7. Выйти из аккаунта → увидеть «Авторизация» без перезагрузки.
8. Повторно авторизоваться → снова получить «Профиль».
