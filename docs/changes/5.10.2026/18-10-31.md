# Изменение: атомарное сохранение Assets

**Дата/время (Москва):** 05.10.2026 18:10:31

## Изменено

- Добавлен PostgreSQL RPC `public.finance_mutate_asset`.
- Создание, изменение и удаление актива теперь выполняются вместе с созданием исторического Assets snapshot в одной транзакции PostgreSQL.
- RPC работает как `security invoker`.
- Владелец операции определяется через `auth.uid()`; клиентский `user_id` не принимается.
- EXECUTE разрешён только роли `authenticated`.
- Application получил единый контракт `mutateAsset` через Finance Memory Port.
- Runtime Finance Memory реализует `mutateAsset` и создаёт один snapshot на каждую операцию.
- Supabase Finance Memory Adapter переведён на RPC для Assets lifecycle.
- Убран прежний двойной путь: `asset mutation → отдельный saveAssetsSnapshot`.
- Добавлена migration `20261005150724_add_atomic_finance_asset_mutations.sql`.
- Finance RLS-политики переведены на `(select auth.uid())` для корректной производительности на больших выборках.
- Добавлена migration `20261005151108_optimize_finance_rls_auth_uid.sql`.
- Расширен unit-тест Runtime Finance Memory для create/update/delete и проверки количества snapshots.

## Проверено

- RPC существует.
- RPC не является `SECURITY DEFINER`.
- `anon` не имеет EXECUTE.
- `authenticated` имеет EXECUTE.
- RLS-политики `finance_assets` сохраняют user isolation для SELECT/INSERT/UPDATE/DELETE.
- Успешный transactional smoke-test прошёл; после rollback тестовые записи отсутствуют.
- Rollback smoke-test прошёл: при ошибке создания snapshot изменение актива не сохраняется.
- Security Advisor не обнаружил новых Finance-проблем. Остались ранее существовавшие предупреждения `private.security_events` и leaked-password protection.
- Performance Advisor после оптимизации Finance RLS больше не сообщает о Finance-политиках; остался только существующий INFO по `private.security_events_type_idx`.

## Ограничения проверки

- Реальный браузерный authenticated E2E через GitHub Pages в текущем окружении не выполнялся.
- Node unit-тесты в текущем окружении не запускались из-за ранее зафиксированного ограничения сетевого окружения.

## Одобрено

- Атомарность текущего состояния Assets и исторического snapshot.
- Сохранение границы Domain → Application → Memory Port → Infrastructure → Supabase.
- Отсутствие userId и Supabase-зависимостей в Domain.
