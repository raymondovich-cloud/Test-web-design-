# Подключение Finance Persistence через Supabase

**Дата:** 05.10.2026  
**Время (Москва):** 17:58:00

## Запрос

Подключить подготовленное Finance PostgreSQL storage к приложению, не нарушая Clean Architecture.

## Реализовано

### PostgreSQL

Созданы user-scoped таблицы:

- `finance_assets`
- `finance_actual_earnings`
- `finance_burdens`
- `finance_mandatory_expenses`
- `finance_cushions`
- `finance_asset_snapshots`

Все текущие Finance записи имеют:

```
user_id → auth.users(id)
```

Для всех таблиц включён RLS.

Основные CRUD policies используют:

```
auth.uid() = user_id
```

Для Assets snapshots разрешены только SELECT/INSERT собственного пользователя.

### Infrastructure

Добавлен:

`source/infrastructure/supabase/finance.memory.supabase.js` — Version 2.0

Ответственность:

- загрузка Finance state из Supabase;
- локальный runtime cache;
- сохранение/обновление/удаление;
- сохранение Assets snapshots;
- нормализация PostgreSQL numeric → JavaScript Number.

Application и Domain не импортируют Supabase.

### Composition Root

`platforms/web/composition/root.js` — Version 1.5.

Authenticated Finance Memory теперь создаётся через:

```
Supabase Client
      ↓
Supabase Finance Memory Adapter
      ↓
Finance Memory Port
      ↓
Application
```

При создании authenticated Finance Memory выполняется hydration из PostgreSQL до отображения Finance.

### Web

`platforms/web/web.js` — Version 3.4.

Authenticated shell теперь ожидает hydration Finance Memory перед render.

### Application

`source/application/finance/finance.js` — Version 5.0.

Persistence operations переведены на async:

- add;
- update;
- delete;
- Assets snapshot.

Domain остаётся синхронным и stateless.

### Presentation

Обновлены:

- `source/presentation/finance/finance.js` — Version 3.6
- `source/presentation/finance/entry.edit.js` — Version 1.7

UI ожидает завершения persistent write перед финализацией операции/перерисовкой.

## Проверка

Через Supabase SQL проверены RLS policies всех Finance таблиц.

Для каждой основной таблицы присутствуют SELECT/INSERT/UPDATE/DELETE policies с условием собственного `user_id`.

Для snapshots присутствуют SELECT/INSERT policies собственного пользователя.

Supabase Security Advisor не обнаружил проблемы с созданными Finance RLS. Единственные возвращённые предупреждения относятся к ранее существующей `private.security_events` и глобальной настройке leaked-password protection.

## Важное ограничение

Полный browser E2E сценарий в текущей среде не запускался.

Node test suite также не запускался из-за отсутствия сетевого доступа в container environment.

Поэтому текущий статус:

**Persistence архитектурно подключён и RLS проверен; browser lifecycle требует отдельной финальной проверки.**
