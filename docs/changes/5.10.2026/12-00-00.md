# Трассировка жизненного цикла удаления и сессии

Дата: 05.10.2026
Время: 12:00 MSK
Статус: диагностический этап

## Изменено

Добавлена временная диагностическая трассировка двух независимых цепочек:

1. Delete → UI → Application → Domain → Event Bus → Memory → UI
2. Supabase Auth → Session State → Web Shell

### Файлы

- `source/core/diagnostics/lifecycle.trace.js`
- `source/presentation/finance/finance.js`
- `source/application/finance/finance.js`
- `source/domain/finance/assets/assets.js`
- `source/core/events/event.bus.js`
- `source/memory/finance/assets.memory.js`
- `source/infrastructure/identity/supabase.identity.adapter.js`
- `platforms/web/web.js`

## Что фиксируется

Для удаления:

- начало операции удаления;
- вызов Application;
- вход в Domain;
- публикация Event Bus;
- сохранение Memory snapshot;
- завершение UI;
- ошибки и отсутствие записи.

Для авторизации:

- обращение к Supabase session;
- результат проверки authenticated/unauthenticated;
- решение Web Shell;
- переходы hashchange/popstate;
- фактический вызов logout.

В трассу намеренно не записываются токены, пароли, содержимое Supabase session и финансовые значения.

## Как включить

Открыть приложение с параметром:

`?trace=1#finance`

Например:

`https://raymondovich-cloud.github.io/LifeGame/?trace=1#finance`

Диагностика сохраняется в `sessionStorage` и доступна через:

`window.LifeGameTrace.get()`

Очистка:

`window.LifeGameTrace.clear()`

Также события выводятся в Console с префиксом `[LifeGame trace]`.

## Следующий этап

После воспроизведения удаления анализируется последовательность событий.

Главная проверка:

- если после Delete появляется `supabase-auth.session.read.completed` с `authenticated: false` — исследуем реальное состояние Supabase;
- если session остаётся authenticated, но Web Shell получает unauthenticated — исправляется Session State/Web Shell;
- если session не меняется и hash не меняется — проблема находится в Presentation/UI;
- если появляется неожиданный `hashchange` или `popstate` — фиксируется источник навигации.

## Одобрено

Пока не меняется визуальный дизайн и не меняется логика авторизации. Этап предназначен именно для установления причины logout.

## План

1. Воспроизвести удаление одной записи.
2. Снять трассу.
3. Определить точку разрыва.
4. Внести минимальное архитектурное исправление.
5. Повторить тест удаления.
6. Только после подтверждения причины убрать либо оставить диагностический слой в зависимости от решения.
