## Что изменено

### 1. UserContext

Создан application-level `UserContext`.

Он содержит только нормализованный `userId`.

Domain не получает UserContext и не знает идентификатор пользователя.

### 2. Finance Memory Port

Создан контракт Finance Memory для Assets.

Application работает с абстракцией Memory и не зависит от конкретного хранилища.

### 3. Assets Domain

Assets Domain переведён в stateless-модель.

Удалены:
- глобальный массив `entries`;
- глобальный счётчик идентификаторов;
- прямой импорт Event Bus;
- прямой импорт системной диагностики;
- прямой вызов Event Bus.

Domain теперь:
- валидирует данные;
- формирует результат операции;
- формирует Domain Event;
- не хранит пользовательское состояние.

### 4. User-scoped Finance Memory

Создана изолированная реализация Finance Memory.

Каждый UserContext получает собственное состояние Assets.

Добавлены операции:
- list;
- create;
- update;
- delete;
- snapshots.

### 5. Web Composition Root

Web Composition Root теперь создаёт UserContext и Finance Memory на границе композиции.

Memory кэшируется отдельно для каждого authenticated user.

Web больше не импортирует конкретный Assets Memory и не подписывается на Finance Event Bus для сохранения snapshot.

### 6. Публичный Finance

До авторизации Finance работает в read-only режиме с пустым состоянием.

Фиктивный пользователь для публичного режима не создаётся.

### 7. Тесты

Добавлены тесты:
- UserContext;
- stateless Assets Domain;
- user isolation Finance Memory;
- сохранение идентификатора Assets при обновлении.

## Архитектурные решения

Зафиксирована схема:

`Presentation → Application → Domain`

и:

`Application → Finance Memory Port → Memory`

Domain не зависит от Memory, Infrastructure, Event Bus или UserContext.

FSI продолжает рассчитываться как производное значение из текущего Finance state.
