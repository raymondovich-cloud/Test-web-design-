## Реализовано
- Отдельный owner-scoped repository для программы, с шифрованием payload и revision compare-and-swap.
- Edge Function boundary проверяет Supabase Auth до создания server-role клиента; пользовательский ID берётся только из verified identity.
- API не принимает от клиента ID/владельца/timestamps/revision и не раскрывает внутренние ошибки.
- Миграция с RLS, закрытыми прямыми grants, immutable owner/ID и DB-managed revision.
- Handler tests и pgTAP тесты; проверка включена в CI.

## Безопасность и ограничения
- Для программы используется отдельный crypto context `purpose=training-program`; он не переиспользует session AAD.
- Текущий Edge composition использует software master-key HKDF для локальной разработки, а не реальный AWS KMS. Production KMS adapter, secret provisioning и key rotation не настроены.
- Remote migration не применялась; UI и Application transport ещё не подключены.
