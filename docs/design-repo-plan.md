# План подготовки LifeGame Design

Версия: 1.1  
Дата: 12.10.2026  
Источник: `raymondovich-cloud/LifeGame`  
Зафиксированный исходный commit: `4bcf36c66918705f5e21e016bef3e36ec799acba`

## Цель

Создать отдельную рабочую копию текущего LifeGame для разработки визуальной системы и проверки интерфейса без прямого изменения основного продукта.

## Архитектурные границы

- `source/design/` — визуальные токены, foundation, компоненты, паттерны, темы и дизайн-ассеты.
- `source/presentation/` — представление и взаимодействия экранов; изменения здесь не должны переносить бизнес-правила из application/domain.
- `platforms/web/` — веб-композиция, bootstrap, manifest и service worker.
- `source/domain/` и `source/application/` остаются источником бизнес-правил; визуальная задача не должна изменять их без отдельного обоснования.
- `source/infrastructure/` и `supabase/` не должны изменяться ради чистого визуального изменения.
- Секреты, реальные пользовательские данные и ключи в репозиторий не добавлять.

## Порядок подготовки

1. Зафиксировать upstream commit и текущее состояние целевого репозитория.
2. Перенести исходники приложения, сохраняя относительные пути и импорты. Выполнено: все 784 отслеживаемых файла исходного коммита присутствуют в целевой ветке.
3. Сохранить исходные change-log файлы как часть snapshot и вести отдельные записи о дальнейших изменениях дизайн-репозитория.
4. Проверить целостность структуры, импорты, тесты и способ запуска.
5. Только после проверки выделять визуальные изменения в отдельные небольшие коммиты.

## Безопасность разработки

- Автоматическая синхронизация исходников отключена. Изменения в дизайн-репозитории не должны запускать `rsync --delete` или перезаписывать рабочие файлы.
- Исходный snapshot закреплён на commit `4bcf36c66918705f5e21e016bef3e36ec799acba`; обновление источника выполняется только как отдельная согласованная операция.
- Перенос в LifeGame выполняется только явным списком проверенных файлов и diff.
- Визуальные изменения не должны менять domain/application, infrastructure, Supabase или security-контракты без отдельного обоснования и согласования.
- Для тестовой ветки включён запуск существующего набора CI-проверок. Фактический результат считается подтверждённым только после завершения workflow.

## Публикация и проверки

- Корневой файл `.nojekyll` предотвращает попытку Jekyll обрабатывать исторические документы с именами, содержащими пробелы, скобки и двоеточия.
- Workflow `database-tests.yml` запускается на push в `chore/design-repo-bootstrap`.
- Успешная публикация и прохождение тестов должны быть проверены по результатам GitHub Actions; наличие конфигурации само по себе не считается подтверждением.

## Правила переноса изменений в LifeGame

- Не синхронизировать целиком ветки и не перезаписывать основной проект.
- Каждый перенос должен иметь явный список файлов и diff.
- Проверять, не затрагивает ли изменение бизнес-логику, безопасность, данные или интеграции.
- Перед переносом запускать доступные автоматические тесты и проверять интерфейс в мобильном и настольном viewport.
- Перенос в основной репозиторий выполнять только после отдельного подтверждения.

## Статус

Исходный snapshot скопирован: в целевой ветке присутствуют все 784 файла исходного commit `4bcf36c66918705f5e21e016bef3e36ec799acba`. Автоматическая разрушительная синхронизация отключена.
